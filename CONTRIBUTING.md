# Как внести свой вклад

Спасибо, что хочешь помочь племени! Здесь коротко: как добавить скилл,
как проверить и как оформить запрос. Камень живёт по правилам — их мало,
но они железные.

## Что тут лежит

- `skills/<имя>/SKILL.md` — скиллы (17 штук, формат агентских скиллов)
- `README.md` + `README.en.md` — русское и английское зеркало
- `SKILLS.yaml` — машиночитаемый индекс скиллов (собирается сам)
- `validate.sh` — страж: проверяет скиллы по стандарту
- `install.sh` — установка в харнесы (Claude Code, OpenCode, Codex, Gemini...)
- `bump.sh` — версии и релизы (`major|minor|patch --release`)
- `RELEASES.md` — журнал изменений

## Как добавить скилл

1. **Один скилл = одно дело.** Скилл решает одну задачу, а не пять.
   Широкий скилл не включается агентом, потому что непонятно, когда он нужен.
2. **Структура:** `skills/<имя>/SKILL.md`, где `<имя>` — латиницей,
   маленькими буквами, через дефис, и обязательно совпадает с именем папки.
3. **Шапка скилла (frontmatter):**
   - `name` — как папка.
   - `description` — что делает И когда включаться. Обязательно раздел
     «Триггеры:» (слова, по которым агент зовёт скилл) и строка `EN: ...`
     — английская копия описания. Без триггеров скилл не найдётся.
     **Триггеры не должны пересекаться с другими скиллами** — одно слово
     на два скилла = двусмысленность, её ловит `tests/golden_triggers.py`
     (гейт в `validate.sh`).
   - `license: MIT` — у нас общая лицензия на всё.
   - `metadata:` с `version:` — версия как в `SKILLS.yaml`.
4. **Объём:** 100-300 строк, максимум 500. Глубокая справка — в
   `references/` (у скиллов с переводом это `references/EN.md`), а не в
   самом скилле: агент грузит ресурсы только когда надо.
5. **RU + EN:** текст скилла на русском, `references/EN.md` — полный
   английский перевод (код и заголовки один в один, без сокращений).
   Проверка паритета — в `validate.sh`.
6. **Никаких секретов и следов машины:** ни ключей, ни путей вида
   `/home/...`, ни имён пользователей. Скиллы читают чужие люди.

## Как проверить перед отправкой

```bash
./validate.sh                 # страж: стандарт, RU/EN-паритет, индекс
bash -n *.sh                  # синтаксис скриптов
./install.sh all --path /tmp/skills-test && ./install.sh status all --path /tmp/skills-test
```

Страж должен сказать PASS — иначе запрос не примут, это не придирка,
а способ не плодить брак.

## Как оформить запрос (pull request)

- **Один PR = одно изменение.** Скилл, фикс, документ — отдельно.
- **Сообщение коммита:** что + почему (например: `feat: скилл
  планирования; добавлен потому что агент не умел составлять план`).
- **Чек-лист в описании** (шаблон уже есть) — пройди каждый пункт.
- Не обновляй `SKILLS.yaml` руками: его собирает `update-index.sh`
  (вызывается сам из `bump.sh`).
- Добавил скилл — добавь строку в `RELEASES.md` и подними версию через
  `bump.sh minor`.

## Что примут, что нет

Примут: скиллы с триггерами, проверенные и с переводом; фиксы опечаток;
полезные ссылки в README.

Не примут: скиллы «на будущее» без реального применения, копии других
скиллов с переименованием, код с хардкодами и секретами, большие
изменения без описания зачем.
