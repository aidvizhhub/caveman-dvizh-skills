Смысл: pkill/pgrep -f матчит командную строку — INCLUDING СВОЮ. Один
неверный выстрел — твой шелл мёртв, работа оборвана. Индустрия решила:
смотри до стрельбы, защищайся скобками, точное имя, мягкий сигнал первым.

## ПРАВИЛА (живые)

1. **СМОТРИ ДО СТРЕЛЬБЫ**: `pgrep -af "паттерн"` — увидь, кого убьёшь,
   ДО pkill. Список разумный → стреляй; нет → стоп.
2. **СКОБКИ ВСЕГДА при -f**: `pkill -f "[о]bs"` — регекс матчит цель, но
   НЕ команду (в её cmdline буквально "[о]bs"). Голый `pkill -f "obs"` =
   самострел.
3. **ТОЧНОЕ ИМЯ лучше -f**: `pkill -x имя` — без риска самострела.
4. **SIGTERM СНАЧАЛА, НЕ -9**: пауза 1-2с → если жив, эскалация
   `timeout 5 pkill -9 -f "[х]с" || true`. -9 первым = данные в мусор.
5. **PID-ФАЙЛ — САМЫЙ БЕЗОПАСНЫЙ**: `kill "$(cat /tmp/x.pid)"` — точный
   PID, никакой охоты. Сервис в systemd — `systemctl restart x`, не pkill.
6. **СЕМЬЯ** (дети не умирают с отцом): `kill -TERM -PGID` /
   `systemctl --user kill app-*.scope` / `flatpak kill app-id`.
7. **ШИРОКИЕ РЕГЕКСЫ ЗАПРЕЩЕНЫ**: «node|python|java|server» без уточнения
   = коллатераль. Только уникальная часть имени.
8. **УБИЙСТВО — ОТДЕЛЬНЫМ ВЫЗОВОМ**, не объединять с работой в одной
   команде (bash -c сам матчится).
9. **ПРОВЕРЬ ПОСЛЕ**: `pgrep -f "[х]с"` пусто = мёртв ✅; не пусто →
   SIGKILL → снова. Потом один новый инстанс (канон single instance).

## ЧТО НЕ ДЕЛАТЬ (запрещено)

- `pkill -f "паттерн"` голым без скобок в любой команде.
- `kill -9` первым. `killall` без -e/-x. Широкие регексы.
- `ps aux | grep имя | awk ... | kill` без исключения grep.
- `pkill` в одной строке `;` с запуском/докачкой — дели на два вызова.

## ГЕЙТ ПЕРЕД СТРЕЛЬБОЙ

- Я посмотрел ДО (pgrep -af) — кого убью? · Скобки [х] или -x? · SIGTERM
  первым? · После проверю «пусто ✅»? · Это отдельный вызов от работы?

Нет хотя бы одного — не стреляй, сначала проверь.
